# 改善提案 — Reysol Pocket

> 作成日: 2026-09-22 / 対象バージョン: v0.5.0（2-1・2-2・2-5・2-6 は実装済み）
> 優先度は「サポーターにとっての価値 ÷ 実装コスト」で判断。上から順に着手する想定。

---

## 0. いちばん大きな課題

**データが手で更新しないと古くなる。** 今のアプリは 32 試合の日程・結果と 2 つの順位表をソースコードに直書きしている。
試合のたびにスコアを入れ、節ごとに順位表を差し替えないと、ファンアプリとして一番大事な「今どうなっているか」が嘘になる。

機能を増やす前に、ここを自動化するのが最優先。

---

## 1. データ自動更新（最優先）✅ 実装済み（v0.7.0）

> **実装した構成は提案と異なります。** API-Football も Cloudflare Worker も使わず、
> 公式ページ（柏レイソル公式の日程／Jリーグ公式の順位表）を GitHub Actions が直接解析する方式にしました。
> 両ページとも robots.txt で許可されており、サインアップもAPIキーもシークレットも不要で、費用はゼロです。
> ライブスコア（下表のB）は未実装のまま残っています。

### 当初の提案（記録）

企画書では「Firebase Cloud Functions（要 Blaze プラン）」としていたが、**この規模なら不要**。次の2段構えを提案する。

| | 方式 | 更新頻度 | コスト |
|---|---|---|---|
| **A. 日程・結果・順位表** | **GitHub Actions の定期実行**で API から取得 → `public/data/*.json` を更新 → Firebase Hosting へ自動デプロイ | 1日2回（朝／深夜） | **完全無料**（public リポジトリなら Actions 無制限、private でも月2,000分の無料枠内） |
| **B. 試合中のライブスコア** | **Cloudflare Workers** を API キーの代理人として1本だけ置き、60秒キャッシュ。アプリはそれを叩く | 試合中のみ 60〜90秒 | **無料枠**（10万リクエスト/日） |

**Firebase を Blaze にしなくていい**のが利点。Aだけ先に入れれば「日程・結果・順位が勝手に最新になる」状態になり、体感の価値がいちばん大きい。Bは試合日にだけ意味がある機能なので後でよい。

### 手順
1. API-Football（または代替）のアカウント作成、J1・ルヴァン・天皇杯・ACLE のリーグIDと柏の team ID を確認
2. `scripts/sync.ts` — API → `public/data/{fixtures,standings}.json` を書き出す
3. `.github/workflows/sync.yml` — cron で `sync` → 差分があれば commit → `firebase deploy`
4. アプリ側は `src/data/schedule.ts` を「JSON を読む + 手書きの上書き情報（チケット販売日・注記）をマージ」に変更
5. 取得失敗時は前回の JSON を保持（古いデータを出し続ける方が空より良い）

> 補足: `schedule.ts` は消さずに **フォールバック＋上書き用**として残す。APIが落ちてもアプリは動く。

## 2. すぐ効く UX 改善（実装が軽い順）

### 2-1. 試合当日モード ✅ 実装済み（v0.4.0）
ホーム最上段の帯が局面で変化する。
- **今日は試合**（当日・KO 3時間以上前）: 天気＋持ち物＋「日立台へ」「チケット」
- **まもなくキックオフ**（3時間前〜）: 秒までのカウントダウン＋同上
- **試合中**: 経過時間＋「公式速報」「DAZN」「掲示板で実況」
- **試合終了**（終了後3時間）: 結果＋**掲示板ボタンを最上段**
アウェイ戦では「日立台へ」の代わりに配信ボタンを主役にする。

### 2-2. 天気（キックオフ時刻）✅ 実装済み（v0.4.0）
Open-Meteo（APIキー不要・無料）でキックオフ時刻の予報を取得。ホームの当日バナーと試合詳細に表示。
雨・寒さ・暑さ・強風のときは持ち物アドバイスを1行添える。予報は16日先まで、取得失敗時は何も出さない。

### 2-3. 共有ボタン
Web Share API（`navigator.share`）で試合カードを共有。「明日の柏、19時から日立台」を友達に送れる。実装は1時間。

### 2-4. カレンダー一括登録
今は1試合ずつ .ics。**「ホーム戦を全部登録」「J1 全試合を登録」**を追加。
さらに **購読型カレンダー**（Hosting に `calendar.ics` を置き `webcal://` で購読）にすれば、日程変更が自動でスマホのカレンダーに反映される。1と組み合わせると強い。

### 2-5. チケット発売日リマインダー ✅ 実装済み（v0.5.0）
販売スケジュールを4段階（プレリク抽選／一次／二次／三次＝一般）で保持し、日程タブの「チケット販売」で切り替え表示。
各段階を .ics で登録でき、開始15分前にアラームが鳴る。プッシュ通知基盤なしでリマインドを実現。

### 2-6. ホーム画面に追加の案内 ✅ 実装済み（v0.4.0）
2回目の訪問から控えめなバナーを表示。Android は `beforeinstallprompt` でその場でインストール、iOS は共有シートの手順を案内。
閉じると30日間は出ない。インストール済み（standalone）では表示しない。

### 2-7. アウェイ戦の「行き方」を出し分け
今は全試合で「経路を検索（公共交通機関）」。海外アウェイ（ラーチャブリー等）では無意味なので、
国内＝経路検索、海外＝会場の地図のみ、に分岐する。

## 3. コンテンツの拡充

### 3-1. 選手名鑑
背番号・ポジション・生年月日・今季の出場/得点。試合詳細の得点者から選手ページへ飛べると良い。
データは公式サイト or API。**ファンアプリとして「ない」のが一番目立つ欠落。**

### 3-2. 試合の中身（得点者・スタメン）
終了試合に得点者と時間、可能ならスタメン。1のAPI連携で同時に取れる。

### 3-3. 対戦相手別の通算成績
「対浦和 直近5試合 3勝1分1敗」。今季データだけでも出せるが、過去シーズンを入れると価値が跳ね上がる。

### 3-4. スタジアムガイドの拡充
日立台の座席図・ゲート・グルメ・駐車場・持ち込み可否、アウェイ席の場所。
初観戦の人と遠征組に効く。公式の初観戦ガイドへのリンクだけでなく、アプリ内に要点を持つ。

### 3-5. 公式ニュース
ホームに最新3件。RSS があれば楽、なければ 1 のワークフローで HTML を取得して JSON 化。

## 4. 通知（Phase 3、ただし前倒しの価値あり）

FCM Web Push。iOS 16.4+ もホーム画面追加済み PWA なら受け取れる。
- キックオフ 1時間前
- ゴール／試合終了（1-B のライブ取得が前提）
- チケット発売開始
- 公式の重要ニュース（移籍・監督人事）

通知を入れると「入れっぱなしにされるアプリ」になる。ただし FCM は Firebase の設定と購読管理が必要なので、2-5（.ics リマインダー）で代替できる範囲は先にそちらで。

## 5. 技術的な改善

| 項目 | 内容 |
|---|---|
| バンドル分割 | JS 293KB（gzip 88KB）。掲示板・もっと・順位表は遅延ロードにすれば初回表示が軽くなる |
| オフライン動作の検証 | Service Worker は入っているが未検証。機内モードで日程・スタジアムが開けるか確認する |
| データ鮮度の表示 | 順位表には「更新: 2026-09-20」がある。日程にも入れる（1 の自動化後は取得時刻を出す） |
| エラー表示 | 現在は失敗時に何も出ない。JSON 取得失敗時に「最新の取得に失敗しました（表示は○月○日時点）」を出す |
| 過去シーズン | `SEASON` は定数。複数シーズンを持てるデータ構造にしておくと 3-3 が楽になる |
| テスト | `utils/fixtures.ts` の成績集計・チケット状態判定は壊れると気づきにくい。ここだけ単体テストを入れる |

## 6. 提案する進め方

```
今  ──▶ ① デプロイして実機で使う（毎日使ってみる）
         ↓
        ② データ自動更新（GitHub Actions）   ← 最優先
         ↓
        ③ 残りの軽いUX改善（共有・一括カレンダー・発売日リマインダー・アウェイの行き方）
         ↓
        ④ 選手名鑑・得点者
         ↓
        ⑤ ライブスコア（Cloudflare Worker）
         ↓
        ⑥ プッシュ通知
```

**まず①**。実際に数試合分使ってみると、ここに書いたどれが本当に欲しいかが変わる。
とくに「試合当日にアプリを開いて何をしたいか」は、使ってみないと分からない。
